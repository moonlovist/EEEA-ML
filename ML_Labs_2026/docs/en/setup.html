Windows · Step-by-step setup

Choose your starting point

Begin with the offline observation route: open the workbook and a measured example in the browser, predict a result and discuss a figure. Then use Python to reproduce and modify the experiment. The data are bundled and each model runs on the CPU.

For the first session, allow 30–45 minutes for setup when Python is new. The teacher can prepare installations before class. Plan for one Notebook and its browser tab at a time. Each experiment uses at most 192 classification observations, 48 journeys or 90 customer records; the neural network has 33 parameters at its default setting.

  1. Download ML_Labs_2026_student.zip.
  2. Open File Explorer with Windows+E. Type %USERPROFILE% in the address bar. Create AI_Course.
  3. Right-click the ZIP → Extract All. Extract into AI_Course. Open the extracted ML_Labs_2026 folder.
  4. Double-click START_HERE.html. Select English, then the workbook or Python primer.
  5. In File Explorer enable View → Show → File name extensions on Windows 11, or View → File name extensions on Windows 10.

You can now read the guides and the 16 baseline and 12 changed-parameter result pages offline. The read-only route uses the packaged results of actual code executions; you can verify their software versions in each report.

1. Open a terminal in the correct folder

In the extracted ML_Labs_2026 folder, click the Explorer address bar, type cmd and press Enter. Run:

dir
py -3.13 --version

The file list should include RUN.cmd, course.py, requirements-core.txt and the notebooks folder. Run each command on its own line. Command Prompt displays a path ending in >; Python’s interactive shell displays >>>. If you see the Python shell, enter exit() and return to Command Prompt.

2. Install or reuse a suitable Python

The classroom target is standard 64-bit CPython 3.13 on Windows x64. Existing Python 3.11 or 3.12 installations can also use the target requirements. The agent course’s Python installation can be reused; this ML course gets its own virtual environment.

  1. Read Settings → System → About → System type. Identify x64 or ARM64. The pinned Windows package route targets x64. For an ARM64 or managed device, the teacher chooses and checks a compatible classroom environment.
  2. Open Python releases for Windows. Open the teacher-selected maintained Python 3.13 patch release and its Files list.
  3. Choose Windows installer (64-bit) for x64. Use a standard CPython build.
  4. Install for the current user. Enable Add python.exe to PATH. Retain pip and IDLE. If the launcher’s all-users option requires administrator access, select a per-user configuration with the installer.
  5. Close the terminal and reopen it from the course folder. Verify py -3.13 --version.

The school technician can preinstall Python on managed machines. A full installer and the course ZIP can be distributed on a USB drive.

3. Create the course environment once

RUN.cmd -m venv .venv
.venv\Scripts\python.exe --version

A virtual environment is a local folder containing the interpreter entrance and this course’s installed packages. The second command should print the selected Python version. Future sessions reuse this folder. Calling its executable directly keeps every command tied to the same environment.

Install the numerical tools:

.venv\Scripts\python.exe -m pip install --only-binary=:all: -r requirements-core.txt
RUN.cmd course.py doctor

Expected final diagnostic: status: READY, followed by the package versions. Installation downloads prebuilt packages and their dependencies. Keep the terminal open until the command finishes. INSTALL_CORE.cmd performs the same installation after the environment exists.

The target dependency versions are listed in requirements-core.txt. The bundled measured examples were produced on macOS with Python 3.8.20, NumPy 1.24.4, SciPy 1.10.1, scikit-learn 1.3.2 and Matplotlib 3.7.4. Windows installation with the target versions is a teacher acceptance step. Use the run’s recorded versions when comparing numerical results.

4. Run a first experiment without Jupyter

RUN.cmd course.py lab 1 --lang en

The terminal prints a short summary and the location of outputs/en/lab01/report.html. Open that file in the browser. Expected counts: 48 journeys, split into 28 training, 10 validation and 10 test rows. The plot shows the training journeys.

Try a later example after its lesson:

RUN.cmd course.py lab 3 --lang en --neighbors 1

This changes k in kNN while retaining the data split and the tree setting. Save each comparison in a different folder when you want to keep both:

RUN.cmd course.py lab 3 --lang en --neighbors 1 --output-dir outputs/comparison_k1

5. Install and open Jupyter Notebook

.venv\Scripts\python.exe -m pip install --only-binary=:all: -r requirements-notebook.txt
RUN.cmd -m notebook

The terminal starts a local service and normally opens a browser tab. If needed, copy the local URL printed in that terminal, including its token, into your own browser. Keep the terminal open during the session.

  1. In the Jupyter file browser, open notebooks → en → Lab00_EN.ipynb.
  2. Select the first code cell. Press Shift+Enter. Its result appears below.
  3. Read a text cell, predict the next result, then execute the next code cell.
  4. A cell marked [*] is running. Wait for its execution number before continuing.
  5. Change one value in an exercise cell and run that cell again. Use Ctrl+S to save.
  6. At the end, use Kernel → Restart Kernel and Run All to confirm that your Notebook runs from top to bottom. The menu wording can vary with the interface language.
  7. Open Lab01 when the warm-up is complete. For later sessions, open that session’s Notebook and run its setup cell first.

You can also double-click START_NOTEBOOK.cmd after installation. Markdown cells contain text to read or edit; code cells execute Python. A None answer marks an exercise waiting for your response. Its feedback is independent of the model cells.

To finish, save the Notebook, shut down its kernel from the interface, then stop the server with Ctrl+C in the terminal and confirm shutdown if prompted.

6. Work with a weak connection or an offline classroom

The teacher can prepare a matching wheelhouse on a Windows x64 machine with the same Python version and copy it with the ZIP. Install from that folder:

.venv\Scripts\python.exe -m pip install --no-index --find-links wheelhouse -r requirements-notebook.txt

Once installation is complete, the exercises use local CSV and JSON data. During setup difficulties, continue with the offline figures, the Python primer and the hand calculations. Record predictions so you can compare them with a later execution.

Troubleshooting

MessageAction
Python command opens the StoreClose the Store. Verify the full installer, reopen cmd, then try py -3.13 --version. The technician can prepare an approved installation.
RUN.cmd is missingOpen the extracted ML_Labs_2026 folder, type cmd in the address bar and run dir. An extra folder level may have been created during extraction.
PowerShell displays PSType cmd to follow these commands. In PowerShell, .\RUN.cmd also launches the local file.
No matching distribution / wheel unavailableCheck Python version and x64 architecture. Use the teacher-selected standard Python 3.11–3.13 environment and its matching wheelhouse. The teacher verifies access to the package index.
ModuleNotFoundErrorRun .venv\Scripts\python.exe -m pip install --only-binary=:all: -r requirements-notebook.txt. Launch Notebook using RUN.cmd -m notebook.
Binary compatibility / NumPy import errorUse this course’s separate .venv and the requirements files together. Keep unrelated environments separate. Ask the teacher to inspect the interpreter path and package versions from doctor.
A Notebook opens as raw textLaunch Jupyter, then open notebooks/en/Lab01_EN.ipynb from its file browser. The .ipynb file stores cells in JSON.
NameErrorRun the setup cell and all earlier code cells in order. Restart Kernel and Run All rebuilds the state.
None exercise feedbackReplace None with your answer. The two hints explain the calculation. Baseline model cells run independently.
SyntaxError / IndentationErrorCheck the reported line, preceding line, quotes, brackets and indentation. Python decimal notation uses a dot, such as 0.5.
Notebook is busy / first plot takes timeWatch [*] and wait for the execution count. The first plot may initialise the font cache. Run one Notebook at a time; use Kernel → Interrupt if an accidental long computation continues.
Browser cannot reach JupyterKeep its terminal open and use the exact local URL printed there. Try RUN.cmd -m notebook --port 8890 if an earlier server occupies the port.
Expected value differs slightlyCompare versions, seed, split and parameters. Keep the analytic hand calculations separate from empirical model scores; report the actual observed values.
Saving failedWork inside %USERPROFILE%\AI_Course in the extracted folder. Save a copy of your work and confirm write access with the teacher.
